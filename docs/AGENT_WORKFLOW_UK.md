# Паралельна робота та економія контексту

Поточне середовище дозволяє чотири одночасні агенти включно з основним.
Збільшення кількості агентів саме по собі не гарантує зменшення сумарних токенів.
Економію дають малі незалежні завдання та спільні артефакти замість дублювання
всієї розмови й повторного читання проєкту.

## Розподіл для наступних етапів

| Роль | Власні файли/результат | Межа |
|---|---|---|
| Координатор | Інтеграція; рішення; перевірка; checkpoint | Один власник остаточного стану |
| Облік | Application finalization service і його тести | Не змінює UI/адаптери паралельно |
| Адаптер | Worker або конкретний протокол і контрактні тести | Не пише журнал маси напряму |
| Інтерфейс/пакет | Qt workflow або build/install | Не змінює accounting policy |

Передавати новому агенту коротке самодостатнє завдання з `fork_turns="none"`:
мета; 3–8 точних шляхів; дозволені файли; контракт; критерії; обмеження.
Не надсилати весь журнал інсталяцій та досліджень. Повторно використовувати
агента для того самого модуля замість починати новий аудит кожного разу.

На старті прочитати `DEVELOPMENT_HANDOFF.md` і відповідний пакет Wxx.
Для навігації використовувати наявний graphify-граф з коротким запитом;
висновок перевіряти у вихідному коді. Не перебудовувати весь граф без потреби.

Кожне завдання має один артефакт або малий набір файлів. Паралельне редагування
того самого файла заборонене без узгодження координатора. Підсумок агента:
зміни; перевірки; обмеження; точний наступний крок. Великі результати — у файлі.

Якщо агент не дає результату або впирається в ліміт, зупинити задачу й
перепризначити конкретні файли; не запускати дублюючі редагування одночасно.
У цій ітерації три допоміжні задачі не повернули файлів; роботу завершив
координатор. Не зараховувати їх як виконані агентами функції.

## Контрольні точки

Оновлювати handoff після завершеного пакета й перед великим дослідженням:
готові файли; фактичні результати тестів; незавершені задачі; активні команди;
наступна команда; відомі помилки. Не записувати токени принтерів чи секрети.
Точний поріг 15% контексту недоступний; контрольні точки робляться завчасно.

Не позначати повний продукт готовим лише тому, що вичерпується контекст.
Наступний запуск відновлюється з останньої точки без повторної інвентаризації.
