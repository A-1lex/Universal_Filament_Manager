# Оформлення та автоматизація UFM Studio

## Робочі простори

Зразок організації — настільний [Bambu Studio](https://github.com/bambulab/BambuStudio):
постійна навігація, окремий простір пристроїв, видимі параметри та стан.
Власні кольори й оригінальна піктограма котушки; сторонні логотипи та ресурси
не копіюються. Це оболонка керування запасами й обладнанням, не готовий слайсер.

З [Mainsail](https://docs.mainsail.xyz/) беремо як напрям розвитку компонування
панелі принтера: стан, температури, камера, макроси, історія і статистика.
Реалізація залишається нативною, без вбудованого браузера.

| Зона | Зараз | Подальше наповнення |
|---|---|---|
| Філамент | Метрики, пошук, таблиця, інспектор, історія | Картки кольорів, фото, партії, місця, масові дії, сканер |
| Пристрої | Список, пошук кандидатів, читання стану | Майстер, телеметрія, AMS/MMU, камера, черга, команди |
| Матеріали | Створення профілю, перелік | Виробник, колір, ціна, щільність, сушіння, сумісність |
| Система | Імпорт, резервна копія, шлях даних | Відновлення, оновлення, журнал, дозволи адаптерів |
| Завдання | У плані | Прив’язка котушок, витрати, попередня перевірка, собівартість |
| Аналітика | У плані | Витрати, браки, собівартість, пороги запасів, поповнення |

## Візуальні правила

- Світла й темна палітра; зелений акцент `#12b76a`, нейтральні поверхні,
  контрастний текст. Колір не є єдиним носієм стану.
- Основні дії поряд з об’єктом; технічні деталі залишаються в діагностиці.
- Невідомий залишок показується словом «Невідомо», а не нулем. Немає вигаданих
  температур чи progress. Стан джерела й давність спостереження потрібно
  зберігати у наступній панелі телеметрії.
- Українська — початкова мова Studio, англійська доступна через `--locale`.
  Майбутній перемикач мови має зберігатися в налаштуваннях.
- Наступні критерії доступності: клавіатурна навігація, фокус, системний
  масштаб 100/125/150/200%, екранний диктор, великі таблиці й resize.

## Автоматизація за рівнем довіри

1. **Виявити:** mDNS/SSDP/обмежений LAN-пошук, USB VID/PID, локальні профілі
   слайсерів. Автоматичні кандидати не отримують права фізичного керування.
2. **Ідентифікувати:** адаптер, реальна модель, серійний номер, capabilities,
   локальна адреса; при Bambu — перевірений сертифікат і явна довіра.
3. **Підключити:** секрети в Credential Manager, повторне підключення з backoff,
   показ офлайн/застарілих даних, відновлення після сну ПК.
4. **Зіставити:** котушка → слот → екструдер → матеріал завдання; QR/NFC/RFID
   допомагають знайти об’єкт, але невідомий тег не створює виміряну масу.
5. **Порахувати:** перевірені факти витрат, відокремлені purge/відходи/брак,
   цілі міліграми, версія політики, журнал доказів.
6. **Застосувати один раз:** стійка ідентичність запуску, транзакція,
   дедуплікація після рестарту, звільнення резерву, атомарна фіналізація.
7. **Пояснити:** журнал рішення й можливість компенсації новою операцією.
   Неоднозначні витрати залишаються на звіряння.

Не вмикати сліпе списування за 100% прогресу або лише ім’ям файла.
Для кількох AMS-котушок потрібні перевірені витрати на кожен матеріал;
коли доступна тільки сумарна оцінка, це видно користувачу до застосування.

## Стек та розширення

Поточний вибір: Python для вже перевіреного ядра і адаптерів, PySide6/Qt Widgets
для нативних вікон, SQLite для локального обліку. Немає потреби переписувати
перевірений журнал тільки через зміну оформлення.

Додаткові мови вводити за виміряною потребою: C++ для Qt/3D і важких обчислень,
Rust для обмежених парсерів великих G-code/3MF. C#/.NET залишається альтернативою
повністю Windows-орієнтованої оболонки, але паралельні UI-реалізації зараз
подвоїли б обсяг підтримки. Передавання між компонентами — версійовані DTO,
без доступу сторонніх адаптерів до SQL-журналу.

Контракт розширення має містити manifest, API version, capabilities,
таймаути, дозволи мережі/файлів, окремий процес для стороннього коду та
контрактні тести. Довільний plugin-код не встановлюється автоматично при discovery.

## Складання

Збірка використовує [PyInstaller onedir](https://pyinstaller.org/en/stable/usage.html):
EXE та бібліотеки поруч. `scripts/build_release_candidate.ps1` створює окреме
lock-синхронізоване середовище `.venv-release` і передає його у folder build;
робочий `.venv312` лишається окремим. [pyside6-deploy](https://doc.qt.io/qtforpython-6/deployment/deployment-pyside6-deploy.html)
є альтернативним офіційним шляхом Qt через Nuitka, який можна порівняти
за часом запуску, розміром і відтворюваністю. Інсталятор, підпис та оновлювач
потрібно реалізувати й перевірити окремо від компіляції.
